# Authored ground-truth manifest for the "ON RE Probe COOP Dvxc1" mission (probe 3).
#
# Source of truth: the authored probe3.bms (designer "OpenNova RE"), saved to the
# JOX game root and read back field-for-field from the live ONED mission model (the
# same bms::File the formats/mission writer serializes). Successor to
# dvxi3_manifest.txt (probe 2, Team Deathmatch) and dvxi5 (Advance & Secure).
#
# Moved to a CO-OP / OBJECTIVE (waypoint) gametype on a fresh terrain (Dvxc1) to
# force the deferred in-match tags the TDM/A&S probes never emitted. Co-op is the
# UNIQUE mode that unlocks both waypoint gates at once: Header.attrib_flags =
# 0x01000000 (Coop, the ONLY mode bit) -> AI_GetTaskTypeFromFlags @0x40DAE0 returns
# task index 2 -> Game_StartMission @0x524360 writes g_GameType @0x24D2128 = 0x30020,
# which satisfies BOTH:
#   - (g_GameType & 0xFFFDFFFF) == 0x10020  -> S2C 0x0F waypoint records (the §5.29 gate
#     @0x523758; off-wire, so only a waypoint gametype produces them; probe2 sent count=0)
#   - (g_GameType & 0x20000)               -> S2C 0x0A objective sub-block 3 (§5.9 gate
#     @0x430357; never witnessed populated)
#
# Deferred tags this probe targets (and the in-session action that surfaces each):
#   - S2C 0x0F waypoint records + team names  -> Co-op gametype + authored waypoint paths
#   - S2C 0x0A objective sub-block 3          -> approach objective/nav markers in play
#   - S2C 0x20 pool-3 sync MID-GAME (D-NET-55)-> AI navigating the authored waypoint paths
#   - guided-weapon record (D-NET-64; never on the wire) -> fire a GUIDED weapon. Guidables
#     come from LOADOUT/armament, not a placed entity: (a) equip a Stinger/Javelin/AT4 kit
#     at an armory and fire it, (b) fly the rocket Little Bird (0x051B) and fire rockets,
#     (c) the placed AI "Indonesian Soldier #4 with Stinger" (0x07F7) fires a STINGER
#     server-side. Rides the C2S 0x0C sub_op path [orig: Entity_SerializeGuidedMissileState
#     @0x447C50], not the 0x0A loop.
#   - 0x46 bit-0x08 respawn-countdown (P2)    -> span a death->respawn cycle, player-sync on
#   - 0x7B field 6 (motd) / 7 (gameName) (P2) -> host with a NON-EMPTY MOTD and Game Name
#   - 0x60 <-> C2S 0x33 MULTI-CHUNK transfer  -> NOT driven by .bms size: 0x60 carries the
#     host session VarList (SERVERNAME/MISSIONNAME/GAMETYPE/CUSTOMTEXT/MISSIONFILENAME/
#     EXP_FANFARE) at 200 B/chunk [orig: NetPacket_WriteReplayDataBlock @0x5071F0]; 0x64 is a fixed 180 B blob
#     [orig: NetPacket_WriteFixed180Block @0x507300], always single-chunk. Force multi-chunk by setting the
#     host MOTD/CUSTOMTEXT to ~300-400 chars (the only >200 B lever) -- this also fills the
#     0x7B motd/gameName fields. (probe2's "~37 KB multi-chunk .bms" rationale was wrong;
#     re-doc follow-up flagged.)
# Re-validation (third independent capture, fresh terrain): statics 0x10, vehicles 0x0D,
# organics 0x0C, markers 0x20, player-list/sync 0x16/0x46, loadout 0x5A, roster 0x6E,
# kill/respawn 0x1E/0x26/0x4E, capture-zone 0x40, vehicle compact + C2S 0x06 -> 0x0A tag2.
#
# Matching loopback capture: .scratch/probe3.pcapng, with paired /profile recordings
#   .scratch/hostprof.sph and .scratch/clientprof.sph (the §5.22 value oracle).
#
# CAPTURE OUTCOME (probe3, validated by nw_dvxc1_groundtruth_test):
#   WON  - 0x0F waypoint records (waypointCount=4, slots p3/6-9; teamNames=0); 0x0A objective
#          sub-block 3 (flags2&3==3, 4xi32, gate g_GameType&0x20000); 0x60 MULTI-CHUNK
#          (total=239: chunk0 200[more] + chunk1 39[FINAL]) + C2S 0x33 re-request; 0x7B
#          gameName="jox01" + extra=0x30020 (= g_GameType on the wire). Every authored entity
#          (0x10/0x0D/0x0C/0x20) reproduced field-for-field.
#   MISS - guided D-NET-64 (no guided weapon fired: only adm=74 rifle/grenades, zero C2S 0x0c
#          guided sub_ops) and mid-game S2C 0x20 / D-NET-55 (AI stayed static, only the load
#          batch). Both remain open for a follow-up capture.
#
# Positions are i32 16.16 world fixed-point (the units the wire 0x0D / 0x20 / 0x10 records
# carry at entity+4/+8/+12). The WITNESSED layer is deliberately ASYMMETRIC (Blue at -x,
# Red at +x, neutral at x=0; a distinct z-bucket per entity TYPE: statics z=-60, starts
# z=-30, organics z=0, vehicles z=+30, objective markers z=+60, guided target z=+90) so an
# axis swap or sign flip in the decoder cannot alias one authored value onto another.
# BMS pos_x = world x; pos_y = -world z; pos_z = the terrain-grounded height. facing_deg is
# the authored yaw; wire BAM = (90 - facing).
#
# wire_tag: which S2C message replicates this entity, by the pool the slot resolves to
#   (D-NET-70; split is by entity CAPABILITY, not editor kind): 0x0C = pool-0 organics
#   (AI/players), 0x0D = pool-1 items/vehicles + destructible/AI objects, 0x10 = pool-2 PURE
#   statics (armory, oil pump/tower), 0x20 = pool-3 markers (player starts, waypoint/nav).
#   type_id is the raw wire itemTypeId (== items.def id - 100000, resolved against the JOX
#   ITEMS.DEF). team 1 = Blue, 2 = Red, 0 = none/neutral.
#   RESOLVED by the probe3 capture: the two "Change Team & Spawn Volume" objects (0x0575 tent
#   / 0x0576 HQ) route to POOL-1 (S2C 0x0D), team-gated (spawn_flags & 0x0010 + team_byte),
#   NOT pool-2 statics. Separately, the four pool-2 armories (handles 0x2000-0x2003) carry the
#   S2C 0x40 capture-zone overlays (Change-Team capability), and the player's spawn-volume
#   association rides the 0x0A player record's mount/vehHdl slot (0x1007 = the tent).
#
# columns: wire_tag  type_id  bms_id  pos_x  pos_y  pos_z  team  facing_deg  group  role
#
